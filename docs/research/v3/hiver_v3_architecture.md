# Hiver Technology — v3 URL-Preserving Architecture & SEO Build Specification

**Version:** v3  
**Date:** 14 August 2026  
**Current host in this plan:** https://hiver.com.np  
**Future canonical host:** DATA REQUIRED — approved canonical domain/brand  

> **Important distinction:** The supplied workbook is a crawl of `nexly.com.au`. Its 253 routes are a reference architecture and benchmark, not Hiver legacy URLs. The v3 package maps them for learning and explicitly prevents accidental redirects or content copying. Hiver’s current legacy inventory is handled separately. [1] [2]

## Executive Decision

Maintain Hiver’s existing human-facing URL paths wherever possible. Rebuild and improve content under the same routes instead of renaming pages for cosmetic SEO reasons. Only redirect a Hiver URL when content is genuinely merged, permanently removed or replaced by a closer canonical target, and only after GSC/analytics/link review. Google recommends preparing an old-to-new URL mapping, using permanent server-side redirects, updating internal links/canonicals/sitemaps and monitoring both old and new properties during a move.[3]

## Stable URL Rules

| Rule | Implementation |
|---|---|
| Host | Keep `https://hiver.com.np` until an approved brand/domain decision exists. |
| Path | Lowercase, hyphen-separated, trailing slash; preserve current Hiver paths. |
| Page names | One canonical URL per intent; no duplicate `/about/` plus `/about-us/`, `/blog/` plus `/insights/` or `/book-a-call/` plus `/contact/` unless the funnel is materially different. |
| Query parameters | Not indexable; retain only for measurement where needed. |
| Archives | Keep only useful canonical hubs; otherwise merge/noindex after GSC review. |
| Reference routes | Never redirect Nexly routes on Hiver by default. |
| Assets | Retain referenced assets; remove from sitemap if not intended for Search; 404/410 only after use/link review. |

## Migration Sequence

1. Export and freeze current Hiver URL, GSC, GA4, backlink and asset inventories.
2. Build/stage the v3 site on the current host with preserved routes; do not combine a domain move, CMS change, major design change and URL rewrite without an approved sequence.
3. Validate every active route, canonical, sitemap, link, form and schema field.
4. If domain migration is approved, deploy one-hop 301/308 redirects to the final new-domain path, update canonical/internal links/sitemaps and verify both properties in Search Console.
5. Keep redirects at least one year; update high-value external links and monitor old/new query and landing-page data. [3]
6. Never use the Nexly reference workbook as a redirect source.
